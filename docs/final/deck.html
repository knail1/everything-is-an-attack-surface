The newest door · the tools you gave your AI

Open the repo. That’s the whole exploit.

A malicious project runs commands and steals cloud credentials the moment your AI assistant opens it. The MCP config loaded before anything checked it (Amazon Q, CVE-2026-12957; same RCE hit Cursor, Copilot, Gemini-CLI).

▸ This is you: Copilot & Claude Code run with your filesystem + shell
  • Poisoned repo / doc images: low-contrast or tiny text hidden in a logo, screenshot, or diagram. Ask the agent to “analyze this directory” and it reads the image and can run the buried commands that fall within its allowed permissions. (Breakpoint Labs)
  • Untrusted design assets: “build this screen from the mockup” is a trust decision. A Figma frame, a Dribbble shot, or a screenshot pasted into a public GitHub issue is just pixels to you — but to a multimodal agent it’s readable text.
  • Chained with CLAUDE.md / .cursor/rules: a poisoned image plus a compromised rules file slips past consent prompts → cloud creds or a reverse shell, no classic malware.
▸ Shut the door
  • Sandbox the repo: open untrusted projects in a devcontainer or throwaway VM — no live cloud creds, no SSO tokens — so “open the project” can’t reach anything real.
  • Gate the config: MCP servers are opt-in — pin each in an enabledMcpjsonServers allowlist (lock it in managed settings), never blanket-approve a repo’s .mcp.json. Guard CLAUDE.md / .cursor/rules with CODEOWNERS + a trust-on-open prompt. The hard stop is the permission allow/deny list — enforced at action time, whatever the config says.
  • Scope the agent: narrow tools, not a raw shell; human-confirm anything that runs a command or sends data out, and block egress to internal IPs.

The idea to take home

A peer agent’s instruction is untrusted input.
Models obey it 100% of the time.

We spent twenty years learning to distrust what a user types. We’re about to hand that same trust, unguarded, to the agents we wire together.

Building it · make peers untrusted by design

You can't prompt a peer into trust. Wire it.

01
Least privilege per agent. The planner gets no shell, only a narrow executor, on an allowlist.
Capability is not permission, applied to the swarm: if a peer can't reach a dangerous tool, a poisoned peer message can't either.
02
Control flow in code, not model handoffs. The orchestrator decides; agents return schema-checked data.
Handoffs pass data, not instructions. A free-text “A hands off to B” is a command B obeys. That's the worm.
03
Split the control plane from the data plane.
Peer output is tainted data in a walled slot, never concatenated into the system / instruction channel.
04
Policy at the tool boundary. Allowlist, arg + egress checks, human-in-the-loop.
Enforced no matter which agent asked or why, so convincing an agent isn't enough to fire the tool.
05
Taint-track untrusted content: quarantine it in a tool-less model.
The research-grade pattern: Willison's Dual-LLM, DeepMind's CaMeL.
Orchestrate with code that distrusts by default, and a poisoned agent is contained to bad data, not a command that worms through your swarm.
Zoom out · the whole talk on one slide

Every door is the same door.

A dependency. An AI-suggested package. An IDE extension. An MCP server. A model file. A retrieved document. A peer agent. A build pipeline. A recruiter’s “take-home.”

Different doors, one bug: untrusted input reaching something that can execute. You don’t have to defend nine surfaces. You have to defend one idea.

The turn · how you shut each door

Same bug, three doors: close them.

Agent hijackuntrusted input + a tool
No raw shell: allowlist tools, least privilege. Treat every document, retrieved file, image, and peer agent as untrusted. Sandbox and human-confirm risky actions.
npm supply chaininstall-time hook
npm install --ignore-scripts (set it globally). Pull from a vetted internal registry (JFrog Artifactory) — a curated proxy that serves approved packages, not the open internet. Verify the package is real before installing. Keep secrets out of the build.
Pickle / model filesdeserializing = executing
Never unpickle untrusted data: use JSON; use safetensors for model weights. Sign and verify blobs.
The through-line: untrusted input reaching something that executes. Don't let it, and don't grant a capability you wouldn't hand the most gullible intern.
